# Заметки для Claude

Проект ведётся на русском: интерфейс, комментарии в коде, сообщения коммитов, тексты
промптов. Владелец работает **только с телефона** — компьютера у него нет, поэтому
всё, что требует сборки, должно собираться в GitHub Actions.

## Как читать дневник

Реестр — в `days/`. Один файл на сутки, `ГГГГ-ММ-ДД.json`. Формат и смысл полей описаны
в `days/README.md` — прочитай его прежде, чем делать выводы по цифрам. Сводка по всем
дням — `days/index.json`.

Когда владелец просит посмотреть питание, разобрать динамику или найти закономерности:

- Итоги уже посчитаны в `totals` (дня, приёма, позиции). Не пересчитывай из `per100` —
  разойдёшься с тем, что он видит в приложении.
- `carbs` включает клетчатку; усвояемые углеводы — `netCarbs`.
- Позиции с `confidence: "low"` или широким `gramsRange` оценены грубо. Если вывод
  опирается на такую позицию, скажи об этом прямо.
- `editedByUser: true` — цифры правил человек, им доверия больше, чем исходной оценке.
- Связь «еда → сахар» ищется по времени: `glucose[].tag` = `post1h`/`post2h` относится
  к ближайшему предшествующему приёму.

## Медицинская рамка

СД 2 типа. Терапия: гликлазид (Диабетон MR), дапаглифлозин (Форсига), тофизопам
(Грандаксин). Практические следствия:

- Гликлазид даёт риск гипогликемии, особенно при пропуске еды и длинных перерывах.
  Поэтому важна равномерность углеводов по приёмам, а не только суточная сумма.
- Дапаглифлозин выводит глюкозу с мочой; на его фоне значения сахара в моче
  неинформативны, а обезвоживание и мочеполовые инфекции — известные риски.
- Не назначай, не отменяй и не меняй дозы. Замечания вида «это стоит обсудить
  с врачом» уместны, рекомендации по дозам — нет.

## Устройство приложения

`app/` — React + TypeScript + Vite, упакован Capacitor в APK. Ключевые модули:

| Файл | Отвечает за |
|---|---|
| `src/lib/ai.ts` | разбор фото: Claude, строгая JSON-схема через `zodOutputFormat` |
| `src/lib/nutrition.ts` | КБЖУ, ХЕ, гликемическая нагрузка — единственное место расчётов |
| `src/lib/db.ts` | IndexedDB: дни и фотографии |
| `src/lib/github.ts` | выгрузка в реестр через Contents API |
| `src/lib/export.ts` | формат файла, который уезжает в `days/` |
| `src/store.tsx` | состояние, сохранение дня, синхронизация |

Правила, которые легко нарушить не подумав:

- **Расчёты живут только в `nutrition.ts`.** Если цифра считается в двух местах, они
  разойдутся, и человек увидит в приложении одно, а в репозитории другое.
- **Модель отдаёт значения на 100 г, а вес — отдельно.** Абсолютные значения приложение
  считает само: так надёжнее, чем просить модель умножать.
- **Локальное сохранение важнее синхронизации.** Если выгрузка упала, запись всё равно
  должна остаться на телефоне, а человек — увидеть, что именно не уехало.
- При изменении формата `days/*.json` поднимай `SCHEMA_VERSION` в `src/types.ts`
  и обновляй `days/README.md`.

## Проверка изменений

```bash
cd app && npm ci && npm run build      # типы + сборка
```

Android SDK в облачной среде недоступен (`dl.google.com` закрыт политикой), поэтому APK
проверяется только в GitHub Actions — смотри workflow «Сборка APK».

Интерфейс удобно прогонять в Chromium через Playwright на вьюпорте 390x844: так видно
то же, что увидит владелец на телефоне.

## Приватность

`days/` содержит медицинские данные. Репозиторий публичный — прежде чем что-то туда
записывать или предлагать записывать, помни об этом и напоминай владельцу про вариант
с отдельным приватным репозиторием для дневника.
